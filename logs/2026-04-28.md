# 2026-04-28 — feature/arch-extensions sprint

## Goal

Break the **orthogonal-basin ceiling** identified across 094 runs in
031–036. No single config exceeds ~5/11 stylized-fact coverage
reproducibly under hyperparameter knobs alone, and 035 stacked-winner
showed effects don't compose — mean dropped to **2.40** vs. singleton
~5/11. The ablation in 036 confirmed `chunk=128` was the destructive
piece; removing it gave the new "best basin" baseline mean **3.20**
(`abl_no_chunk128`: chunk=24, h=96, init=0.1, Sprint 2 + twopop+Hawkes).

Plan: implement six architectural tiers behind config flags
(default-off → backward compatible), then run a 100-config H20
overnight batch to learn which tier — alone, paired, or all-stacked —
breaks the 5/11 ceiling.

## What was done

Branched `feature/arch-extensions` off `feature/custom-autograd-step`
(HEAD `f6e42c1`). Implemented all 6 tiers as one commit (`9a41983`).

**New code**:

- `ecomd/models/agent_memory.py` — `AgentMemoryGRU` per-agent memory
  with `(N, d_memory)` state. Mean-pool into external context.
- `ecomd/models/isab_pairwise.py` — `ISABPairwisePotential` using
  manual einsum + softmax (NOT `torch.nn.functional.SDPA` — Flash
  and mem-efficient backends both break `create_graph=True`
  double-backward). Two cross-attention layers via M=64 inducing
  points. Memory at N=10K is 2.5 MB per scores matrix.
- `ecomd/models/potentials.py` — `StochasticPairwisePotential` extended
  with `type_aware_heads` (K² last-layer heads, shared backbone,
  ~768 extra params at K=4) and `pair_features_extra` (none /
  distance / inner_prod / signed_diff / all). Symmetrization
  preserved across all modes.
- `ecomd/physics/integrator.py` — `OverdampedLangevin` extended with
  `jump_lambda`, `jump_scale` (training-mode `tanh(s)`-coupled drift
  correction; inference-mode discrete `Poisson(λ·dt)·N(0,σ²)`
  sampling) and `update_mask` (per-agent multi-timescale gate).
- `ecomd/models/ecomd.py` — 14 new config flags + constructor wiring;
  threaded `h_agent` through `step()`, `rollout_chunk()` (custom-fn
  + grouped-checkpoint + no-checkpoint paths), and `run()`.
- `ecomd/models/bptt_step_function.py` — `EcoMDStepFunction` forward /
  backward extended to save and propagate gradient through `h_agent`,
  mirroring the existing `h_regime` pattern.

## Results / findings

- **Default-off equivalence**: with all new flags at defaults, rollout
  output is unchanged from pre-arch-extensions baseline (sanity
  check via the existing test suite).
- **Per-tier smoke**: each tier runs forward+backward on a 20-agent
  rollout under both default and Sprint 2 (`bptt_custom_function=True`)
  paths. 5+ params receive non-zero gradient in every case.
- **All-6-stacked smoke**: under Sprint 2 + ISAB pairwise + Tiers
  1.1, 2.1, 2.2 active (1.2/1.3 are silent under ISAB), 27/29 params
  receive non-zero gradient. Sprint 2 still works as memory bound.
- **End-to-end mini-train (Mac, Tier 1.1, N=80, 3 iters)**: finite
  loss (1.40 → 1.01), finite gradient norm, training_log.json written.
  Full DDP path works via `ecomd.training.train_distributed`.
- **100 configs all parse cleanly** through `EcoMDConfig + LossWeights`.

## Open questions / blockers

1. **Tier 3.1 ISAB on H20 fp32**: smoke pass on Mac CPU; must verify
   `create_graph=True` double-backward works under CUDA at N=10K.
   Mitigation: manual einsum (no SDPA backend dependency); fallback
   would be to use a no-attention pairwise.
2. **Tier 1.1 + Sprint 2 backward memory at N=10K**: per-step h_agent
   buffer is `(10000, 16) × 4B = 640 KB` — saved twice per step
   (input + output). Fits trivially.
3. **Composition surprise (044)**: 035 hyperparameter-stacking
   produced destructive composition. We don't know if architectural
   stacking will too. The `stack_no_isab` cell is the most aggressive
   (5 tiers active simultaneously); if it degenerates to 2-3/11, the
   composition problem is fundamental and we'll need
   mixture-of-experts / curriculum strategies in the next sprint.
