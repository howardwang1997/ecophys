### Verdict on stacked-winner hypothesis

The "three-lever stack reaches GARCH-parity 5-7/11" hypothesis is
**falsified** in its simplest form. Need ablation to identify which
knob breaks the stack.

### Phase F-ablation designed (036_stacked_ablation)

40 configs (4 cells × 10 seeds), each removing ONE knob from the
stacked config:
- `abl_no_sprint2` — revert bptt_custom_function: false

- `abl_no_h96` — revert hidden=48
- `abl_no_init01` — revert init_state_scale=0.05

**Decision rule**: cell whose mean recovers ≥ 4-5/11 names the saboteur.

Bonus: `abl_no_chunk128` is effectively a 10-seed re-test of Phase H's
`s01_h96` "winner" which was based on only 2 seeds. If that drops to
~3/11 too, the original Phase H signal was lottery, not a real cell.

#### CRITICAL FINDING: top runs enter different "basins of competence"

The 9 runs with score ≥ 5/11 partition into orthogonal fact subsets:

| Top run | passes | misses |
|---|---|---|
| `pcfix_chunk24_seed1` 7/11 | hill+gl+ag+fa+acf²+ck+lv | ar, df, vc, **zb** |
| `pc_chunk128_seed1` 6/11 | hl+ag+fa+acf²+lv+**zb** | ar, gl, ck, df, vc |
| `ph_init_s01_h96_seed1` 6/11 | **ar**+gl+fa+**df**+lv+**vc** | hl, ag, acf², ck, zb |

**No single run passes simultaneously**:
- autocorr_returns + zumbach_asymmetry + hill + acf²

Different hyperparam choices push the model into different fact subsets.
There is NO single basin in our current design that covers all/most facts.

### Hypothesis updates

The "ceiling at ~5-7/11" is **not a single ceiling**. It's a
**fact-coverage ceiling**: each basin caps at ~5-7/11 because the model
can't simultaneously fit moments that require different dynamics
(autocorr=0 conflicts with zumbach>0, etc.).

**This implies fundamental loss / training redesign more than
architectural change**:
- Distribution-level loss (W2 / score-matching / GAN) would force the
  model to fit the WHOLE distribution, naturally covering all facts.
- Multi-stage curriculum: train to basin A, then add basin B's facts as
  loss term, etc.

   under multi-seed?
3. If we train an ENSEMBLE (3 different basin configs running in
   parallel, eval each on 11 facts, take best of 3), do we reach

### Architecture sprint — feature/arch-extensions

After ablation results landed, decided architectural changes (not pure
loss redesign) was the right next step: hyperparameter knobs are
exhausted, but we hadn't yet tried per-agent memory, heterogeneous
force kernels, jumps, multi-timescale, or attention.

Branched `feature/arch-extensions` off `feature/custom-autograd-step`
(HEAD `f6e42c1`). Implemented all 6 tiers as one commit (`9a41983`).

**New code**:

- `ecomd/models/agent_memory.py` — `AgentMemoryGRU` per-agent memory
  with `(N, d_memory)` state. Mean-pool into external context.
- `ecomd/models/isab_pairwise.py` — `ISABPairwisePotential` using
  manual einsum + softmax (NOT `torch.nn.functional.SDPA` — Flash
  and mem-efficient backends both break `create_graph=True`
  double-backward). Two cross-attention layers via M=64 inducing
  points. Memory at N=10K is 2.5 MB per scores matrix.
- `ecomd/models/potentials.py` — `StochasticPairwisePotential` extended
  with `type_aware_heads` (K² last-layer heads, shared backbone,
  ~768 extra params at K=4) and `pair_features_extra` (none /
  distance / inner_prod / signed_diff / all). Symmetrization
  preserved across all modes.
- `ecomd/physics/integrator.py` — `OverdampedLangevin` extended with
  `jump_lambda`, `jump_scale` (training-mode `tanh(s)`-coupled drift
  correction; inference-mode discrete `Poisson(λ·dt)·N(0,σ²)`
  sampling) and `update_mask` (per-agent multi-timescale gate).
- `ecomd/models/ecomd.py` — 14 new config flags + constructor wiring;
  threaded `h_agent` through `step()`, `rollout_chunk()` (custom-fn
  + grouped-checkpoint + no-checkpoint paths), and `run()`.
- `ecomd/models/bptt_step_function.py` — `EcoMDStepFunction` forward /
  backward extended to save and propagate gradient through `h_agent`,
  mirroring the existing `h_regime` pattern.
