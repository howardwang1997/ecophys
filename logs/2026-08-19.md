## Session 1 (04:50)

### Goal

Identify free or openly accessible datasets that can support the current policy-fidelity/NCS feasibility work without purchasing data or opening frozen Aave target rows prematurely.

### What was done

- Audited official documentation for SQD Portal/Network, Envio HyperSync, Google Blockchain Analytics, Tardis, Binance public data, AEMO NEMWeb, and Elexon Insights/BMRS.
- Inspected documentary metadata only for two claimed public Aave datasets; no frozen Aave configuration-program rows were queried or downloaded.
- Separated static open datasets from free query services and free samples, since their reproducibility and redistribution rights differ.

### Results / findings

- SQD documents all nine relevant EVM networks (Arbitrum, Avalanche, Optimism, Polygon, Base, Gnosis, BNB, Linea, Scroll) and historical block/transaction/log access. Its public Portal is free for development/evaluation, but production pricing is pending. It is the strongest candidate for a target-free source qualification followed by the frozen nine-chain B0 extraction.
- Google Blockchain Analytics provides an independent Google-maintained replica for only Arbitrum, Avalanche, Optimism, and Polygon among those nine chains. BigQuery's first 1 TiB of monthly query processing is free; this is suitable for a bounded cross-provider audit, not the complete B0 source.
- Envio HyperSync is a useful backup source but is proprietary, requires an API token, and offers a development/testing free tier rather than an open dataset.
- Tardis exposes the first day of every month without an API key, including incremental L2 updates and snapshots. This is enough for observation-bridge reconstruction and sparse feasibility tests, but first-of-month selection cannot support a representative confirmatory market claim.
- Binance publishes daily/monthly spot and futures trades, aggregate trades, and klines with checksums. These data support order-flow and stress-context work but do not provide historical L2 reconstruction.
- AEMO NEMWeb and Elexon BMRS provide strong non-DeFi mechanism backends. Elexon's current Insights APIs require no key and BMRS data have an explicit attribution-based open-data licence.
- Fan and Sun's six-chain Aave paper claims a Zenodo dataset at DOI `10.5281/zenodo.17898640`, but the Zenodo API currently returns 404, so it is not presently usable as a public dataset.
- The available RED-LIQ-2026-v1 Zenodo deposit is CC-BY-4.0 but its own README/schema metadata are internally inconsistent about 2023--2024 coverage versus timestamps entirely in May--July 2026. Treat it as an unaudited external artifact, not ground truth.

### Open questions / blockers

- SQD must pass a pre-registered, target-free nine-chain qualification for coverage, deterministic pagination, joins, gaps/duplicates, cross-provider block hashes, rate limits, and data-use terms before any Aave target query.
- SQD's free development endpoint is not a durable production SLA; extracted immutable shards and hashes are required for reproducibility.
- The configured canonical `.Codex/memory/` directory is absent in this checkout, so lasting findings were recorded here but not copied into long-term memory.

### Next steps

1. Freeze and commit a zero-target SQD qualification protocol.
2. If it passes, freeze B0-v2 and materialize the nine-chain Aave configuration-program dataset with provenance and content hashes.
3. In parallel, use Tardis first-of-month files for the L2 observation-bridge feasibility gate and AEMO/Elexon for a non-DeFi mechanism backend.

## Session 2 (16:53)

### Goal

Turn the free/open-data audit into frozen executable gates, keep the available heterogeneous compute useful,
and update the NCS execution record without opening frozen target rows or buying data.

### What was done

- Preregistered, implemented, tested and committed exp138 (`9357600d1`) before issuing any SQD block-stream
  query. The client is structurally limited to metadata, finalized heads and header-only finalized streams.
- Ran exp138 as three disjoint CPU/network shards on the two V100 hosts and RTX2060 host; returned and hashed
  all artifacts.
- Preregistered and committed exp139 (`1046a8d01`), deployed an isolated snapshot, and ran the frozen CUDA
  scaling matrix on both V100s and the RTX2060. Kept every failed mechanics gate visible.
- Preregistered and committed exp137 (`b9fe0569d`), then fixed shard-count-dependent seeds and an incorrectly
  localised global gain gate in `30fd294d9` before aggregate analysis. Unit tests, ruff and CPU smoke pass.
- Verified all sample SHA256 values before use. The first full GOOG path ran on the RTX2060; the first result
  was retained and rerun after the seed fix.
- Probed the official Tardis Binance sample URL from the Mac and a compute-node egress. Both returned Cloudflare
  HTTP 403; no sample was acquired.

### Results / findings

- exp138 Q0a PASS: 9/9 datasets, 36 repeated windows, 90 total requests; repeated block content, numbering and
  parent links were exact. Stream median/p95 latency was 0.424/0.777 seconds and retry fraction was 2.78%.
- exp139 overall FAIL: 6/6 `N=500` cells passed across three GPUs; 0/14 `N>=2,000` cells passed. The two V100s
  reproduced the same seed-specific NaNs/non-finite long rollouts. HBM was not limiting (`N=10,000` reserved
  12.81 GiB), so the production ceiling remains `N=500` pending a stability study.
- The RTX2060 default `ecophys` Conda environment has a PyTorch/driver mismatch. Its existing
  `ecophys-g0-regression` environment is compatible and completed CUDA work; no driver change was made.
- exp137 global PASS: five of five paths cleared the relevance gate. Across 947,911 eligible transitions,
  927,811/927,811 visible queue changes reconstructed exactly. Median combined gain was 0.271 nats/event and
  declined to 0.080/0.023 with 5/20-event staleness.
- The correct-seed GOOG model/audit dictionaries were exactly identical across the pre/post scheduling-only
  commits. All five canonical paths were completed on RTX2060 CUDA. CPU replications for AAPL, MSFT and SPY
  also passed; their largest held-out combined-NLL difference from CUDA was 0.0164 nats/event.
- All eight held LOBSTER archives were uploaded to private R2 under
  `free/lobster_samples/2012-06-21/`; five non-duplicate symbols were used in exp137.

### Open questions / blockers

- Both V100 SSH/Tailscale paths timed out during sample transfer and left partial files; no partial shard was
  run. Primary exp137 results were completed on the reachable RTX2060, with Mac CPU portability replications;
  a V100 replication is queued for when connectivity returns.
- Q0b still needs frozen non-Aave join fixtures, independent-provider hashes and immutable export before any
  target extraction.
- Tardis sample automation is blocked by external HTTP 403; LOBSTER cannot substitute for crypto coverage.
- G0 still lacks a genuinely new invariant-measure estimator, and exp139 adds a production stability blocker.

### Next steps

1. Rerun one exp137 path on a V100 after connectivity returns as a portability replication, not a new primary
   result.
2. Freeze Q0b, a full continuous-time Hawkes baseline and a small EcoMD stability diagnosis; do not launch
   formal WP2 or buy L2 before their gates.
3. Commit result artifacts, the execution board, Plan v4 status and lasting memory after final verification.
