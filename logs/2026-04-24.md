## Session 10 — Phase 2 入口：EcoMD v0 架构落地

**Goal**: 实现 Phase 2 的 EcoMD v0（plan_v2 §Phase 2），跑通 1000-agent 训练 demo，并与 LM99/GARCH 做初步 stylized-facts 对比。架构必须不需要重写即可演化到 Phase 3（MACE-lite）和 Phase 4（非平衡热力学）。

### 关键架构决策（通过 plan mode 与用户确认）

1. **价格形成机制可插拔**
   - `PriceFormation` Protocol：`ExcessDemandPrice`（默认，LM99 风格）+ `ReadoutPrice`（ablation）
   - 默认机制把 `s_i[0]` 视为每 agent 的"仓位"——这让 #10 volume/vol 关联天然涌现（见下）

2. **Overdamped Langevin**（v0 ship）+ `LangevinIntegrator` Protocol 预留 `UnderdampedLangevin` 接口
   - 更新公式：`s_{t+1} = s_t + (f_cons + f_diss)/γ · dt + √(2γT·dt) · ε`
   - γ、T 通过 log 参数化保正性；两者都可学
   - 保守力 / 耗散力 / 随机力每步分三路记录——C2 在 Phase 4 直接能消费

3. **势函数分解** `U_θ = V_pairwise + V_external + V_dissipation`
   - V_pairwise：symmetric MLP on `[s_i, s_j, |s_i - s_j|]`，O(N²)（v0 可接受，Phase 3 换 MACE-lite）
   - V_external：per-agent MLP on `[s_i, context]`（context = `[log_p, vol, r_{t-1}]`）
   - V_dissipation：显式二次项 `λ · Σ |s - s_prev|²`（**不在 θ 内**，保持保守/耗散可识别）

4. **训练 Loss**：moment-matching（ACF(r²) + Σleverage + soft-Hill α）
   - 都可微；ACF/leverage 由 FFT-free 直接求和；Hill 用 sigmoid 软 top-k
   - v0 **不含** fluctuation-theorem loss——C2 留 Phase 4

5. **BPTT**：truncated chunks（默认 chunk=64），每 chunk 一次 optimizer step；grad clipping = 1.0

### 关键 research finding：**truncated-BPTT × moment-matching 的外推差距**（honest reviewer-2 结果）

这是一个有价值的 **负面结果**：

- **原因 A（主要）**：`chunk_steps=32 < max_lag=20` 让每个 chunk 的 ACF(r²) 估计只能基于 ~12 个有效独立样本，信噪比低，训练信号把模型引向 **chunk 头部 transient 大**（在短窗口内"虚假匹配"moment），但这种 transient 在 2000 步推理时会累积成**非平稳漂移**。
- **原因 B**：LR 3e-3 对随机初始化的 MLP 势函数过大，梯度尖刺频繁（|∇|=137 at iter 0）。grad clipping 1.0 拦了一部分但势函数仍在参数空间里大幅度游走。
- **原因 C**：每轮 `init_state` fresh → 模型从不体验长期 steady state，只见过 chunk 头部的 relax-from-random 动力学。
- **架构红利独立存在**：尽管训练崩了，**#10 corr(V,|r|)** 从 +0.16（smoke 粗糙架构）→ +0.84（trained），远超 LM99/GARCH——designated-position ExcessDemand 机制的自带优势没被训练破坏，只被"放大"。

**架构是对的，naive 训练策略是错的。** 这对 Paper A 来说其实是好故事：
> "我们证明了天然含守恒律的 price formation 机制（designated-position ED）在**零训练**下已命中 volume/vol clustering（stylized fact #10），而纯 moment-matching truncated BPTT 无法稳定训练长期动力学。Paper A 的训练策略是 XXX（更长 chunk / 持久化环境 / 代理损失）。"

### 下一步修正清单（v0.5）

按优先级：

1. **LR 降到 1e-3 + 更 warm-up** 或用 cosine schedule
2. **使用持久化环境 state**（训练时不 reset，跨 iter 保留 s/price_state，只 detach gradient）——这直接解决"模型只见 transient"的问题
3. **max_lag 与 chunk_steps 同比缩**（例如 max_lag=8 配 chunk=32），以免 loss 被尾部噪声支配
4. **Activation checkpointing** 启用，以便 chunk=128 不 OOM
5. **Detach warm-up 头 N 步**（loss 只计算 chunk 后半），让 loss 不奖励 transient
6. 加入 **Wasserstein return-distribution loss**（POT 包已装）作为辅助信号，不容易被 "transient hack" 骗过

如果 v0.5（1-2 天工作量）能把数字跑到 ≥7/11（打平 GARCH）就可以交 M2 milestone。

## Session 11 — v0.5 训练策略修正（接 Session 10 的 negative finding）

**Goal**：解决 Session 10 发现的 truncated-BPTT 外推差距问题，把 EcoMD 从 4/11 推至 ≥5/11 且数值在合理区间。

### 改进点

基于 Session 10 的 root-cause 分析，四项打包修正：

1. **Persistent environment state**：跨 iter 保留 `(s, s_prev, price_state)`，只在 iter 边界 `.detach()`。模型不再每轮从随机 init 起 relax，而是见到连续轨迹。
2. **Warm-up detach（16 步）**：每 chunk 前 16 步的 return 不计入 loss。阻止优化器把信号塞进 transient。
3. **LR 降到 1e-3 + cosine schedule**（3 iter 线性 warmup，后退火至 1e-4）。
4. **max_lag 缩到 8**（对应 chunk=32 的有效独立样本数）。

**新基础设施**：
- `ecomd/training/train.py` — `train_ecomd(...)` 提炼出来，支持上述三个开关
- `experiments/004_ecomd_v0p5/{config.yaml, run.py}` — 独立实验；复用 003 的 baselines 与数据管道
- 输出 `five_way_comparison.md`（v0 trained 作为对照列保留）

### 架构

MACE-lite (去 SO(3)，保留 permutation-invariance + ACE 高阶展开)：

```
s ∈ R^{N×d}
  → k-NN in feature space (k=16 Mac, 32 H20)
  → Gaussian RBF distance encoding (B=8)
  → K-class soft prior (K=4 via MLP + softmax)
  → 2-body message m_ij = MLP([z_i, z_j, R_ij, s_i-s_j])
  → h⁽¹⁾ = Σ_j m_ij                    [sum aggregation, permutation-invariant]
  → h⁽²⁾ = MLP_3body(LN(h⁽¹⁾) ⊙ LN(h⁽¹⁾))    [3-body via tensor product]
  → h⁽³⁾ = MLP_4body(LN(h⁽¹⁾) ⊙ LN(h⁽¹⁾) ⊙ LN(h⁽¹⁾))   [4-body]
  → U_i = MLP_readout(concat(h⁽¹⁾, h⁽²⁾, h⁽³⁾, z_i))
  → V_pairwise = Σ_i U_i
```

核心数学：`(Σ m_ij) ⊙ (Σ m_ik) = Σ_{j,k} m_ij ⊙ m_ik` 包含 k=j (2-body) 和 k≠j (3-body) 项——**O(N·k) 计算量拿 3-body 表达力**，不需要 O(N·k²) 枚举三元组。MACE 2022 核心 trick。

### 架构对比

| | v0.6 PairwisePotential | v1 MACELitePotential |
|---|---|---|
| 图 | Complete O(N²) | k-NN sparse O(N·k) |
| Body order | 2 | 2 + 3 + 4 |
| 类别先验 | 无 | K=4 soft assignment |
| 距离编码 | raw |s_i−s_j| | Gaussian RBF B=8 |
| 规模 | N ≤ 10³ | N ≤ 5×10⁵ |

## Session 16 — H20 首轮训练结果分析 + 诊断方案

**Goal**：分析用户在 H20 上完成的 v1 / v1+ 首轮 200-iter 训练结果，定位问题并给出验证性 rerun 方案。

### 背景

用户在 H20 独立 push 了 `11a15ea`（兼容性补丁）和 `97dec86`（v1/v1+ training_log.json）。Mac 端拉取后分析。

### H20 环境 / 补丁摘要（`11a15ea`）

- **NCCL 2.19.3 挂**：`nproc_per_node ≥ 4` 报 Cuda 101 `invalid device ordinal`。临时方案 `DIST_BACKEND=gloo`。
- **k-NN OOM**：N=10⁴ 下 `s.unsqueeze(1) - s.unsqueeze(0)` 峰值 12.8 GB，chunked 到 chunk_size=2048 后降到 2.6 GB。
- **chunk_steps 64 → 24**：为 MACE-lite body_order=4 在 96 GB HBM 腾空间。

### 训练结果（200 iter × 4 rank, 约 107s 单轮）

| 指标 | Target (SPX 日线) | v1 final | v1+ final |
|---|---|---|---|
| `acf_sq` (vol clustering) | **+0.254** | −0.083 | −0.283 |
| `leverage` (asymmetry) | **−1.30** | +0.40 | +1.56 |
| `hill_α` (tail index) | 2.68 | 2.26 | 0.54 |
| total loss | ↓ | 2.76 → 0.72 | 2.98 → 1.32 |

**两个核心发现**：

1. **v1 / v1+ 双双无法建模 vol clustering**：`acf_sq` 全程负值，与 target `+0.254` 反向。
2. **v1+ 比 v1 全面更差**：Mac smoke 原本两者持平，H20 scale 下 v1+（Student-t × learnable β）不稳，iter 100 出现 `grad_norm=677` 尖峰，`hill_sim` 震荡 0.3–11.6。

### 根因推断

**最主要嫌疑**：`chunk_steps=24, warmup_steps=16` → **只剩 8 步 BPTT 梯度窗口**。
- v0.5 原基线是 chunk=64/warmup=16 → **48 步 BPTT**。
- vol clustering 的 ACF(1) 需要 O(10²) 时间步才能形成可观测信号，8 步根本不够。
- 同时 `max_lag=16` 超出可用窗口，ACF 在训练时实际未被有效测量。

次要嫌疑：
- gloo 后端带宽限制（但本次 per-iter 531ms 在 N=10⁴ 下说明通信不是主瓶颈）。
- v0.6 Mac 就观测过 learnable β × heavy-tail 不稳定，H20 scale 放大。

### 诊断 rerun 方案

新增：
- `experiments/006_ecomd_v1/config_h20_diag.yaml` — **N=4000, chunk_steps=64, warmup_steps=16** → 恢复 48 步 BPTT 窗口，其余字段与 v1 完全相同。
- `scripts/h20_launch_v1_diag.sh` — 启动脚本，输出到 `results_diag/`（不污染原 `results/`）。

**判读规则**：
- 若 diag run 的 `acf_sim` → **正数并接近 +0.25**：确认 chunk_steps 是病根。下一步走 activation checkpoint 路径恢复 N=10⁴。
- 若 `acf_sim` 仍负：问题是架构/物理层面（可能是 OverdampedLangevin 在大 N 下过度耗散，或 price_formation 平滑度），需深挖。

**v1+ 暂不 rerun**：learnable β × heavy-tail 先不动，等 v1 base 稳定再叠加。

### Bug fix

- `ecomd/inference/run_large.py`：与 `train_distributed.py` 相同的 `DIST_BACKEND` 硬编码问题已修（默认走 env var）。否则推理阶段 NCCL 仍会挂。

## Session 17 — H20 v1 连跑三轮诊断 (ORIG / DIAG / CLIP100) + Mac v1 ablation A-H

**Goal**：确认 v1 MACE-lite 训练失败的根因；若是优化问题就修 knob，若是架构问题就找到具体组件。

### H20 三跑结果对比 (v1 body=4 per_node, N=10K)

| 变体 | 改动 | acf(r²) final | leverage | hill | 结论 |
|---|---|---|---|---|---|

**三跑共性**：acf_sim 始终无法稳在正半轴。说明**优化能到更好点，但架构本身无 vol-clustering 吸引子**。

### Mac v1 ablation A-D（保持 v0.6 训练 recipe）

| 变体 | 只改一个 | acf(r²) eval |
|---|---|---|
| A | 无（纯架构切换）| −0.002 |
| B | k=199 完全图 | −0.002 |
| C | body=4 | −0.002 |
| D | body=4 + LN off | −0.002 |

**四个完全一样**。力量级 probe 确认：v1 架构 V_pair 量级 O(N)，v0.6 是 O(N²)，force 差 60-190×，被 Langevin 噪声完全淹没。所有 A-D 实际在跑**纯 Langevin + Gaussian aggregate demand → Gaussian white noise**。

### Mac v1 ablation E-H（引入 F1-F4 修复）

新增 3 个 MACELite knob：`readout_mode ∈ {per_node, per_edge, hybrid}`, `readout_multiplier`, `readout_init_gain`.

| 变体 | 配置 | acf(r²) eval | 形状判断 |
|---|---|---|---|
| E F1 scale=200 | per_node + V×200 | −0.002 | flat |
| F F2 gain=5 | per_node + readout init ×5 | −0.003 | flat |
| G F3 per_edge | complete graph + 每边 scalar readout | +0.032 | 微微有信号 |
| **H F4 hybrid** | complete graph + per_edge + per_node body=4 | **+0.202** | ⚠ **flat，不是 peak-decay** |

### 关键诊断（今日最重要的单一观察）

**H 的 acf(r²) = 0.202 在单 lag 上**，但 per-lag 曲线几乎 **flat at 0.19**（lag 1 = 0.18, lag 19 = 0.21）。真实 SPX lag-1 = 0.45 然后 slow decay 到 0.11；GARCH 相似；v0.6 也相似。**H 是经典 Goodhart — 把单一均值 target 用"常数 noise regime"作弊满足**，物理上不是 vol clustering。

**结论**：v1 MACE-lite 架构**至少在当前 price-formation + Langevin 框架下无法生成真实 burst-decay 动力学**。不是 bug，不是 undertrain，是 architecture-market 错配。
