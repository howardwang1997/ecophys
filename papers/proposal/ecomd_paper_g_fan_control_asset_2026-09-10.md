## Source capability actually established

The [JavaFAWT repository](https://github.com/UPNAdrone/JavaFAWT) describes
individually commanded fans, WebSocket-to-PWM control, repeatable command
sequences and a 6-by-4 experimental array. Its recorded velocities are
derived from pressure, temperature and density, not an independent second
velocity instrument. The selected README does not establish measured RPM
for each archived command. A command interface is not yet a complete
executed-actuation record.

The [published study](https://doi.org/10.1016/j.array.2026.100957), Array30
(July2026),100957, describes 24 duty-percentage inputs and 24 downstream
velocity outputs, with measurements across seven distances. Indexed
Sections4,6,7.1–7.2 and the abstract were read; the full article was not
obtained. It already benchmarks spatial architectures and simple mixing
baselines. Its advertised forward-learning task must not be promoted to
independently verified closed-loop control.

The official Hugging Face API confirms a public, ungated
[UPNAdrone/WindTunnel](https://huggingface.co/datasets/UPNAdrone/WindTunnel)
dataset, created November18,2025, containing `DatasetV2.csv`,
`DatasetV2_velocities.csv`, `.gitattributes` and `README.md`. The dataset
card contains only a MIT license declaration; it supplies no additional
field dictionary or acquisition protocol. No CSV header or data row was
read. These facts identify an existing resource, not a new post-closure
release, and do not certify its row-level semantics.

## What is needed to turn the resource into a truth/control asset

| Capability | Established here | Still needed for the intended inference |
| --- | --- | --- |
| Physical intervention | Individually specified fan duty commands | Executed duty/RPM, timing, actuator response, settling and reset conditions |
| Measurement | Pressure-based downstream velocity labels described | Calibration, zero offsets, conversion conventions, uncertainty and an independent velocity reference |
| Paired files | Pressure and velocity CSVs listed | Stable row/run identities and a verified transformation between them |
| Dynamic replay | Software supports prescribed command sequences | Archived sequence identity, clocks, acquisition windows, retained history and ambient state |
| Confirmation | One experimental source identified | Untouched whole-run partition, assignment justification and independent same-target replication |
| Scientific contribution | Existing spatial and mixing baselines identified | A matched physical explanation test that survives those baselines and sensor/actuator alternatives |

Unknown here means unqualified by the inspected sources, not proved absent
from the underlying dataset. File count does not prove independent sensor
lineages. A pressure file and its transformed velocity file cannot establish
independent replication of the same velocity response merely by being two
files. Similarly, 24 sensor locations are not a full velocity-vector volume
or an independently measured divergence/energy-balance field.

The prospective estimand family is restricted to experimental downstream
sensor response to a specified fan-command vector at a declared distance
and acquisition window. Physical velocity, electrical power, fluid power,
closed-loop policy value and PDE derivative truth require additional
measurement and state contracts. No such quantity is inferred from the word
power used for a duty-percentage input.

All 24 commands and the shared flow matter for interference: the effect of
one command is conditional on the other commands, fan geometry and ambient
state. Repeated records from the same run cannot automatically be treated
as independent assignments. Temporal grouping and command-generation rules
must be resolved before a time-separated or whole-run confirmation split.
No claim of randomization or train/test leakage is made from missing metadata.
