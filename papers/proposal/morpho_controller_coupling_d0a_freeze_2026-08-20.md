**Transport status:** the first v1 call returned HTTP 404 before any role payload and wrote no result. The

**Formal result:** v2 failed the unique non-public allocator gate because Steakhouse USDC has three non-public

## Decision boundary

This protocol is frozen before requesting any reallocation history. D0A asks whether three independent Morpho
curators can be tied, without behavioral inference, to a named vault, a declared automated allocation system and
an unambiguous current non-public allocator role.

D0A is deliberately narrower than the prospective D0 support gate in the T0 plan. A pass authorizes a separately
frozen D0B event-identity/support audit. It does not establish that a particular transaction was generated by a
particular codebase or strategy, and it does not authorize amounts, rates, utilization or outcomes.

## Why this gate is necessary

The official `morpho-blue-reallocation-bot` repository proves that reusable APY-band and utilization-equalising
software exists. Its checked-in strategy configuration names several vaults, but the actual vault whitelist and
reallocator private key are environment secrets. A vault-specific parameter in that repository is therefore a
deployment lead, not proof that the repository executed a live transaction.

Likewise, an allocator role only proves permission, and a regular transaction cadence only describes behavior.
Neither identifies automation. D0A accepts automation only when the curator/operator itself publicly describes a
named system as automated and the named anchor vault can be resolved independently.

## Allowed queries and retained fields

D0A may call only the three fixed public Morpho API allocator-role endpoints in the YAML contract. It may retain:

- vault version, chain ID and fixed vault address;
- current allocator address and role-grant transaction hash;
- raw-response SHA-256, HTTP status and retrieval time;
- the fixed documentary source URLs and predeclared policy-family labels.

It may not call allocation history, transaction history, market state, APY or position endpoints. It may not
retrieve or infer transaction cadence, asset amounts, supply/borrow balances, rates, utilization, prices,
liquidations, yields or post-action behavior. Raw API responses are not committed.

The known Ethereum V1 Public Allocator contract is excluded from private-operator identity. A common public
allocator cannot establish independent control.

## Frozen hard gates

D0A passes only if all conditions hold simultaneously:

1. all three fixed anchor-vault role endpoints return a valid, nonempty allocator registry;
2. after excluding official public allocator contracts, each anchor has exactly one current non-public explicit
   allocator; zero is unsupported and more than one is ambiguous;
3. the three non-public allocator addresses are pairwise distinct;
4. the three predeclared operator labels are distinct and every cluster has an operator-authored automation
   statement tied to the named anchor;
5. at least two distinct predeclared policy-family descriptions are represented; and
6. the result contains no forbidden endpoint, raw response or numerical market field.

The uniqueness rule is intentionally conservative. Owner/curator inherited permissions and undocumented manual
keys are not relabeled as bots. A failed current-role binding does not contradict the operator's historical
statement; it only means the public evidence cannot support the planned transaction-level study.

## Stop rules and next stage

Any hard-gate failure closes this field route before historical events. Do not add another vault, relax
uniqueness, infer automation from cadence, or query outcomes to rescue it. A new candidate universe would require
a new protocol and an untouched future interval.

If D0A passes, D0B must be committed before requesting histories. D0B will retain the T0 thresholds of at least
three independently controlled clusters, two chains or independently described policies, 12 active
vault--market edges, 300 complete reallocation transactions, 90 calendar days and 50 multi-non-idle-market
transactions. It must first qualify canonical receipts against an independent finalized index, including dense
blocks and high log indices.

## Resources

D0A is capped at one CPU core-hour, 10 MB of retained derived metadata, three public API requests and zero GPU
hours. The two V100 workers and RTX 2060 remain idle.
